# Quick Start

> 中文版本：[快速开始](../zh/quickstart.md)

This guide deploys MWX-ISP on a Linux VPS with Docker Compose and PostgreSQL,
then walks through the first login and RADIUS smoke test. The admin UI uses TCP
`1816`, RADIUS authentication uses UDP `1812`, accounting uses UDP `1813`, and
RadSec uses TCP `2083`.

## 1. Install on a VPS

Install Docker Engine and the Docker Compose plugin on an Ubuntu or Debian VPS.
Point a DNS name at the server before installing if you want Caddy to issue a
public HTTPS certificate automatically. Then run:

```bash
git clone https://github.com/bjo163/mwx-isp.git
cd mwx-isp
sudo bash scripts/vps-install.sh
```

The installer creates private credentials in `/opt/mwx-isp/.env`, builds the
application image, and starts PostgreSQL, MWX-ISP, and Caddy. It prints the
generated admin password once: save it securely. The web port is bound to
localhost behind Caddy; RADIUS ports are exposed for NAS connections. The
installer enables a daily update timer when systemd is available. Review the
[`README.md`](https://github.com/bjo163/mwx-isp/blob/main/README.md) before
production use.

Set `MWX_ISP_DOMAIN` in `/opt/mwx-isp/.env` to the public DNS name for automatic
HTTPS. The default `localhost` is suitable only for local checks. Do not expose
PostgreSQL to the public network.

## 2. Sign in

Open `https://<your-domain>/admin/` (or the local proxy URL during setup) and
sign in with:

- Username: `admin`
- Password: the one-time password printed by the VPS installer

Change the password after signing in. Existing installations keep their current
admin password when updated. For manual Compose setup, copy `.env.vps.example`
to `.env`, replace every `CHANGE_ME` value, and run `docker compose up -d --build`.

## 3. Try the sample records

A completely empty installation gets clearly marked synthetic sample records
on first startup. Existing databases are left alone. Sample NAS devices and
RADIUS users are disabled by default. Create or enable records only in an
isolated test environment.

Use the English admin UI to explore **Customers**, **Packages**,
**Subscriptions**, **Billing**, **Network & Alerts**, and **RADIUS**. Customer,
package, invoice, and payment numbers are generated by the application.

## 4. Test RADIUS locally

The repository includes a small RADIUS client. On a development database, add a
NAS at `127.0.0.1` with shared secret `testing123`, then create an enabled test
user and run:

```bash
go run ./cmd/radtest auth \
  -server 127.0.0.1 -secret testing123 \
  -username test1 -password 111111

go run ./cmd/radtest flow ...   # auth + accounting start + accounting stop
```

For a real network, register the NAS using the source IP it sends from and a
strong shared secret. Allow only the needed RADIUS traffic through the VPS
firewall. Validate authentication, accounting, and Disconnect behavior with
your actual NAS before serving customers.

## 5. Back up and update

```bash
cd /opt/mwx-isp
sudo scripts/backup-db.sh
sudo scripts/vps-update.sh
```

Backups are written locally; copy them to secure off-server storage as well.
The automatic updater follows `main`, creates a pre-update database backup,
waits for the new app health check, and attempts a source/image rollback if the
update fails. Review the deployment scripts and backup retention for your own
operating requirements.
